WHAT IS DEBTSPIRAL?
-------------------
An early-warning system that detects emerging debt spirals using
trajectory analysis (trends & ratios), not static thresholds.
Built for a hackathon. 100% synthetic data — no PII.


CURRENT STATUS: FUNCTIONAL END-TO-END
--------------------------------------
All layers are built, connected, and tested.

  [DONE] ML Pipeline
    - Synthetic dataset: 800 users x 12 months, 8 cohorts
    - 16 engineered features with trailing windows
    - Forward-window labeling (t+1..t+3)
    - XGBoost model + isotonic calibration
    - Metrics: AUC 0.8267 | PR-AUC 0.6097 | Brier 0.1401
    - Median lead time: 2.0 months
    - FP rate on recovering users: 4.6%

  [DONE] Backend Services (FastAPI)
    - scoring.py     — loads XGBoost + calibrator, returns risk 0-100
    - explain.py     — SHAP TreeExplainer, top 6 features
    - rules.py       — 8 reason codes, severity-weighted flagging
    - projection.py  — Scenario A vs B over 3/6/12 months
    - notify.py      — Twilio WhatsApp + fallback, deduplication
    - features.py    — 16 features with as_of cutoff
    - loop_detector   — 3-condition deterministic spiral detection
    - simulator.py   — shared month-stepper for projections
    - session_store   — in-memory persona store

  [DONE] API Endpoints
    GET  /health           — model status, persona count, uptime
    GET  /personas          — all personas with real risk scores
    GET  /personas/{id}     — detail + SHAP + assessment
    POST /score             — compute risk for a persona
    POST /transaction       — process txn, flag, generate nudge
    POST /project           — project debt scenarios
    POST /reset             — reset personas to initial state

  [DONE] Frontend (React + Vite + Tailwind)
    - GPay-inspired light theme, phone mockup frame
    - 10 screens, 7 components
    - Connected to real backend API
    - Real risk scores, SHAP charts, debt trajectory
    - Live what-if projections from /project endpoint
    - Payment flow with real flagging + nudge banners
    - Persona switching with API reload
    - Reset calls backend /reset

  [DONE] Frontend-Backend Integration
    - App loads persona data from API on startup
    - DebtSpiral screen shows real SHAP + trajectory
    - Transaction flow calls /transaction endpoint
    - What-if slider debounces API calls to /project

HIGH PRIORITY (Hackathon Impact)
---------------------------------

1. IMPROVE PERSONA C RISK SCORE
   The model gives Persona C a score of 5 (LOW) even though the loop
   detector confirms a spiral at month 4. The model was trained on
   synthetic data with different distributions. Options:
   - Retrain with adjusted class weights or threshold
   - Adjust Persona C's history to trigger higher model scores
   - Use a blended score: model + loop detector combined
   This is the #1 issue for demo credibility.

2. ADD LOADING STATES & ERROR HANDLING
   - Show skeleton/spinner while API calls are in flight
   - Show error toast if backend is unreachable
   - Graceful degradation to stub data when offline

3. HISTORICAL RISK SCORES IN TRAJECTORY CHART
   Currently the trajectory chart shows debt bars (from history).
   Better: compute risk score at each month (call /score with
   as_of_month for each month) and show both debt + risk curves.

4. COST OF NEXT DECISION DISPLAY
   The /project endpoint returns cost_of_next_decision but the
   frontend doesn't display it yet. Add a card showing:
   "Your next Rs X discretionary purchase costs Rs Y in extra
   debt over 12 months."

5. NOTIFICATION DEMO
   Wire up Twilio WhatsApp sandbox so the nudge actually sends
   a WhatsApp message during the demo. Just needs .env config:
   TWILIO_ENABLED=true, TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN,
   DEMO_WHATSAPP_TO.
